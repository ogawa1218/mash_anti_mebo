## 課題1への対策：公開速度を最優先にする

### 原則：「80%の完成度で公開 → 後から図解追加」

今の制作フローは1記事あたりの工数が多すぎる：

```
【現在のフロー（1記事7-8工程）】
本文5000字 → 図解5枚生成 → サムネ3案 → X告知文
→ 10連スレッド → stand.fm概要欄 → 設定メモ → 公開

⬇ 変更

【改善フロー（1記事3工程）】
本文 → サムネ1枚 → 公開
（X告知・図解・概要欄は翌日以降に追加）
```

## 課題3への対策：戦略文書のスリム化

### 現在の問題

```
note/CLAUDE.md → 35,000字超（全情報が1ファイルに詰め込まれている）
親/CLAUDE.md → ローンチ戦略など別の情報
会話引き継ぎ → 毎回コピペで渡す必要
→ 重複・矛盾・読み込みコストが膨大
```

### 改善案：3ファイル構成に再編

```
note/CLAUDE.md（3,000字以内）
  → 「今やること」だけ。現在のPhase・今週のタスク・品質基準
  → Claude Codeが毎回自動で読む唯一のファイル

note/STRATEGY.md（アーカイブ）
  → ペルソナ・収益モデル・Phase計画・デザインシステムなど
  → 必要なときだけ参照

note/HISTORY.md（ログ）
  → 各セッションの決定事項・完了タスクの記録
  → 振り返り用
```
